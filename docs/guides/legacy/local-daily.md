# 本地定时日报与飞书推送

## 已确认的需求与范围

2026-10-23：用户授权启用本机定时生成和群推送。北京时间周一至周六14:00，每排程日最多一条；周一和休市使用最近已收盘交易日，卡片标明实际行情日期。周日不发。当天已确认成功的手动试跑可登记为该日已发送，启用后不重复发送。只使用一套行情与评分代码。

当前先理顺本地，不上传本地日报到云端。线上网站保留，其定时任务暂停、日报服务入口关闭、飞书发送关闭。本地生成的报告ID不是线上报告ID，因此本地卡片没有公网详情链接。

## 运行结构与恢复

macOS launchd -> scripts/local-daily.py tick -> 本机 /api/reports -> 同一评分引擎与本地数据库 -> 完整冻结卡片 -> 飞书

- `cn.feardesk.local.server`：登录后启动，仅监听127.0.0.1:5173，进程退出后恢复。
- `cn.feardesk.local.daily`：14:00触发，并每五分钟检查同日任务；时间判断始终使用Asia/Shanghai，不依赖系统时区。
- 一轮最多推进约四分钟；每次接口调用另有60秒超时。检查点由现有接口持久保存，后续检查使用同一请求身份继续，不在每轮新建任务。
- 生成失败和投递失败分别记录。最多六轮接口错误，明确拒绝最多三次发送尝试并间隔五分钟；生成任务自身仍遵循现有三次失败和累计工作预算。
- `sent/sending/unknown`均不自动重发。发送前原子保存sending并领取数据库投递身份；遇到断网或不能确认的回执记unknown，需人工核对群消息。
- 仅处理本日，午夜后不补发昨日。暂时无任务或尚未到点只结束本轮，不停用周期服务。
- 对行情和飞书保留HTTPS证书校验，显式使用macOS系统证书包；不会将“不确定”当成成功。

## 本机资料与操作

以下配置均在被Git忽略的 `.sites-runtime/local-daily/` 下：

- `config.json`：已有飞书机器人、Python与Node绝对路径，文件权限0600。
- `state.json`：每日生成、检查点和投递状态，权限0600；不含机器人地址。
- `runner.lock`：防止两个本地调度执行器同时运行。
- `server.log/server-error.log/daily.log/daily-error.log`：服务日志，不输出凭据。

`python3 scripts/local-daily.py status` 查看状态；`tick`执行本日检查，仍受日期与去重约束；`install`只生成两个LaunchAgent配置，不偷偷加载或覆盖已有同名任务。`serve`启动已有本机服务，发现缺失或未知数据库时拒绝使用空库代替。

电脑需开机、联网、不进入系统睡眠，并保持用户已登录；屏幕可以关闭。完全退出浏览器或Codex不影响launchd运行。关机期间无法按时发送；当天恢复后会检查，过去日期不补发。不承诺外部行情源可用或飞书远端恰好一次。
