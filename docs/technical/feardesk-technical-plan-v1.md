## 3. 技术边界与接口提案

复用现有 ChatGPT 访问保护、D1、Yahoo 日线解析、评分引擎、财报缓存、冻结快照与飞书投递保护。新接口名称与字段为提案，架构阶段再冻结。

| 入口 | 工作 | 返回及副作用 |
|---|---|---|
| GET 日报状态与最新指针 | 只读 current、任务、独立 delivery | 不初始化行情、不修复任务、不生成、不发送；空库明确空态 |
| GET 冻结日报 id | 按 id 读取快照 | 历史页面不随 current 改变 |
| POST 手动生成 | 校验身份与 requestId，持久受理，source=manual、sendIntent=none | 202 taskId；重试同 requestId 返回原任务或结果；无 14 点限制 |
| 云端定时受理 | 固定服务入口；读取服务端目标规则及原发送授权 | 与同目标任务合并，单独保留 schedule 来源与投递意图 |
| 后台推进/恢复 | 仅执行器可调用；有 fencing token、时间预算与审计 | 执行一个有边界的步骤或回收过期 attempt；不向网页暴露能力凭据 |

用户操作超时后展示“受理状态待核对”，用同 requestId 查询/重试，不能生成新的 requestId 无限叠加。拒绝未支持 action，不能让拼写错误落入默认运行路径。所有状态 GET 均禁止缓存敏感跨用户结果，响应不含服务器配置值。

## 4. 任务、恢复与幂等

概念数据包括 logicalJob、requestIntent、attempt、stepCheckpoint、inputRevision、immutableReport、currentPointer；并非现在就承诺新增七张表，架构阶段可合并存储。

logicalKey 使用目标交易日、冻结观察池版本、算法与卡片版本、可比较输入修订。requestId 解决同一次操作的网络重试；logicalKey 合并不同来源同目标生成；业务内容 hash 复用相同报告。三者不能互相替代。尚未确定目标日期时先创建受理请求，由后台解析后原子归并；禁止请求内先取完整行情再受理。

每个来源保留独立 requestIntent，manual 永远 none。schedule 的意图只来自当前既有、明确启用的自动投递授权。到达顺序无关；调度晚到并且生成已完成时，可复用已验证结果走独立投递路径。生成任务状态 ready 不受飞书 failed/unknown 降级。

```text
受理并持久化 -> queued -> claim attempt(token, lease) -> running
                                      |
                   SPY -> 交易日判定 -> 冻结观察池/修订
                                      |
                     分步行情与评分 -> 财报 -> 完整性校验
                                      |
                incomplete/error --预算内--> retry_wait
                                      |
                             完整 -> 原子发布 -> ready

独立唤醒器 -> 扫描到期 queued/retry_wait 和过期 running
过期 running -> interrupted -> 新 attempt；旧 token 后续写入全部拒绝
预算耗尽 -> failed；页面读操作始终不推进这条链
```

已确认基线：后台每小时只扫描/续跑已有queued/retry_wait/租约失效任务，不创建额外交易日任务，不执行飞书发送。租约/无进度120秒用于失效判断；观察与接管可能等到后续云任务，取消60秒恢复承诺。每片目标20秒、硬预算25秒（留出响应后30秒边界余量），正常交接不消耗失败尝试；失败/中断最多3次，退避30/120秒只作为最早可执行时间。累计执行预算30分钟，不含等待小时唤醒；分片先预留预算，崩溃不能逃过计数。不再承诺受理起30分钟墙钟终态。首次请求可通过有边界的waitUntil推进一片，后续不依赖网页；不能通过自循环Promise延长生命周期。

每次 bars/scores/earnings/job/report/pointer 写入都需要条件化 token 与版本验证；不能只在发布前查锁。外部 fetch 在事务外完成，暂存候选数据，再以短事务/CAS 有条件提交。过期进程不能污染新 attempt 或其他市场总览更新。存量单标的 syncOne 调用与日报执行器的写权限必须共同协调，不能只锁 logicalJob。

## 5. 数据一致性与最新交易日

纽约交易所日历判定最新应收盘日 D，包含休市、夏令时与提前收盘；日历来源与本地可审计维护方式在架构阶段确定。SPY 判定最新可用已收盘日 d。若 d<D 且截面完整，保存/复用 d 并标明行情延迟；若 SPY 已为 D 而其他股票缺 D，则 incomplete，禁止退回旧共同日期制造完整假象。未收盘数据禁止入正式报告。

冻结观察池与输入修订；评分使用同一 SPY 修订；财报会影响评分时必须等重算完成。跨步骤发生修订则显式重启一致性检查，不把一半旧评分和一半新评分打包。可使用版本化输入快照或受控发布读视图，两种存储细节留待架构选择。

预热 score=null 可以行情完整，但显示有效评分比例；日期未知财报明确未知，不填 0。所有股票目标日行情/评分日期、重算状态必须验证；前日评分不足仅影响比较样本，不冒充当日缺失。

正式 report 保存、task.reportId 关联及 currentPointer 更新须一次原子提交。利用 D1 条件 SQL 与 batch 的真实事务语义，先做回滚和竞争验证；当前测试里 Promise.all 模拟 batch 不证明真实原子性。current 按 tradeDate 单调，再按可比较 inputRevision；同日不可比较修订冲突需显式处理，禁止靠完成时间抢占。旧任务迟到只成为历史快照，不能回退 current。

## 6. 网页行为与状态

```text
打开/刷新/恢复网络 -> GET最新指针与状态 -> 无记录: 空态
                                    -> 有记录: GET快照并展示
手动生成 -> 持久受理202 -> 展示独立任务状态 -> 轮询状态
新current版本 -> 获取完整新快照 -> 一次替换网页视图
历史id -> 固定快照；可提示新日报，但不自动跳转
```

正常 30 秒、活动任务 5 秒轮询；隐藏页面暂停，恢复可见或网络恢复立即 GET。只维持一条轮询链，取消旧请求或比较响应序号，拒绝晚到旧响应覆盖新快照。任务生成状态、行情完整性、交易日、生成时间、数据延迟与飞书状态分别展示。刷新按钮与生成按钮有独立 busy 状态，生成中仍可刷新读取已保存日报。

故障时保留最后一次成功快照并显示读取失败，不清空日报误导用户。登录过期要求恢复登录，不能绕过身份检查或继续有副作用轮询。
