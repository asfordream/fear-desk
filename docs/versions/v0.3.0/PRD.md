# FearDesk：交易规则与观察 PRD

日期：2026-10-30
状态：用户已授权基础功能开发；页面布局与核心规则已确认，以下补充列明本次采用的保守默认。
阶段：实现与本机验证；发布状态见 release.md。
原型：[规则卡片与观察清单](prototypes/overview.svg)

## 1. 目标与场景

用户每日查看自己的交易规则、知道哪些观察池股票触发规则、还要等几个交易日、哪些已经到期需要人工查看。下午两点由现有飞书机器人发送独立的观察提醒。计算使用固定代码，不调用大模型，不自动下单。

## 2. 已确认的范围

| 项目 | 确认内容 |
|---|---|
| 页面 | 新增固定入口“交易规则与观察”；上方规则卡片，下方每日观察清单 |
| 规则类型 | 自动筛选、人工检查在同一处管理，明确标签；人工项不自动判定通过 |
| 维护 | 新增、编辑、删除、启用/停用、上下拖动排序，顺序持久保存 |
| 展示顺序 | 网页及独立提醒使用同一排序；顺序只影响展示，不改变条件 |
| 股票范围 | FearDesk 当前观察池；新增股票自动纳入后续筛选；移出股票停止新筛选及已有提醒，保留历史 |
| 停用与删除 | 停止新筛选，并停止该规则已有倒数和待处理事项的消息；历史保留 |

| 内容 | 每次展示启用规则，即使没有触发也发“暂无倒数或待处理标的” |
| 日常清单 | 新增触发、倒数中、今日到期、到期待处理、历史 |
| 到期处理 | 网页手动标记已处理；到期后每日继续提醒直至处理，历史保留 |
| 数据位置 | 本地数据库，页面和提醒共用同一份规则及触发记录 |

## 3. 第一条自动规则：单日跌幅超过 5%，等待三个交易日

### 已确认

- 比较相邻两个美股交易日的收盘价，单日收益率严格小于 -5%；等于 -5% 不触发。
- 触发日为 T（第零天），观察日为之后第 3 个美股交易日 T+3。
- 周末、美国市场休市跳过，不按北京时间的自然日计数。
- 同一股票再次满足本规则，按最近一次触发重置观察日；旧触发保留证据。
- 这是进入观察的提醒，不将到期自动视为可以买入或已经开仓。
- 已确认使用现有行情库中同口径的复权收盘价计算跌幅，不另找行情数据源。

### 建议计算与展示口径，待工程评审

- 使用已确认的复权口径；工程评审核对现有字段含义，避免重复复权。原始价格和复权依据保留可追溯信息。
- 收益率 =（本日复权收盘价 / 前一有效交易日复权收盘价 − 1）×100%。比较原始精度，显示可四舍五入，不能以显示值决定是否超过阈值。
- 必须取得实际相邻交易日收盘数据。缺数、未收盘、异常复权时不判定触发或未触发，显示“待数据核对”。
- 每天下午两点按即将到来的美国交易时段展示倒数，不能把北京时间日期直接当作行情日期。
- 例：周五触发、下周无休市，则周一第 1 天、周二第 2 天、周三第 3 天；周三北京时间下午两点单独提醒今日到期。
- 美国交易日历需版本化；不能只用工作日或股票实际有无成交条数倒数。个股停牌不能改变市场交易日历。

## 4. 页面与操作

### 规则卡片

固定拖动柄、序号、名称、类型、启停、规则摘要、当前/待生效版本、编辑/删除入口。新规则可添加为人工文字项；首期自动规则使用受支持的模板参数，不将任意自然语言直接转成自动计算。

### 观察清单

展示规则、股票、触发跌幅、实际触发交易日、观察交易日、剩余交易日、状态、上次变动原因、处理操作。默认先今日到期和待处理，再倒数中；组间按规则卡片顺序排列，组内按观察日排列。

- 未到期：倒数中。
- 到期：今日到期；之后未处理为待处理，继续每日提醒。
- 人工标记：已处理；记录时间和可选备注，停止当前提醒，不推断成交。
- 再次大跌：新触发覆盖当前倒数，旧触发标为被后续触发替代；不删除旧证据。
- 页面标明实际行情日期、更新时间、来源、缺数和服务不可用状态。
- 标记等私人操作复用现有本机会话与同源校验；手机不能直接访问本机地址。

## 5. 独立飞书提醒

标题：FearDesk · 交易规则观察。内容按已保存顺序展示所有启用规则，再展示今日到期、待处理、倒数中、新增触发。没有股票时仍保留规则内容和空状态。人工检查项展示文字，不自动打勾。

建议沿用北京时间周一至周六14:00的排程，周日不发（交易日与休市实际发送范围待最终确认）。与恐慌日报采用独立的任务及投递身份；一张发送失败不阻止另一张发送。不能以已有恐慌日报回执跳过规则提醒。

- 发送前先保存当天规则版本、顺序、触发清单和行情日期快照。
- 同一排程日、目标、卡片类型只自动投递一次；sending/unknown 不盲目重发。
- 明确成功回执才标记发送成功。仅受理或生成成功不等于送达。
- 失败时网页保留错误与最近成功时间。复用现有有限重试与检查点经验。
- 多规则导致卡片超长时须按平台限制验证；不可静默省略规则或股票。首期分片策略待工程评审。
- 卡片只提供查看入口；处理操作在本机网页进行，不增加飞书应用回调权限。

## 6. 数据设计草案

| 记录 | 保存内容 |
|---|---|
| 规则 | 稳定ID、类型、名称、展示顺序、启停与归档状态 |
| 规则版本 | 条件参数/人工检查文字、生效交易日、创建时间、版本号 |
| 触发事件 | 规则版本、股票、行情日、比较价格、跌幅、来源证据 |
| 观察事项 | 关联触发、观察日、倒数/待处理/已处理/被替代状态 |
| 操作记录 | 编辑、停用、删除、重置、处理时间和备注 |
| 提醒快照/投递 | 排程日、原内容、任务进度、尝试次数、确认/失败/未知状态 |

删除采用归档，不物理删除历史。规则重排不制造新的计算版本。页面读取持久快照，不依赖用户开着浏览器生成结果。私人库与凭据不提交Git。

## 7. 方案比较

| 方案 | 优点 | 代价 | 建议 |
|---|---|---|---|
| 简单文字规则表＋每日现算 | 改动小 | 倒数重置、历史版本、人工处理难以追溯 | 不满足已确认范围 |
| 版本化规则＋触发记录＋持久观察事项＋独立投递 | 能支持修改、倒数、人工处理及历史追溯；沿用本机服务 | 初期需要明确状态、迁移与幂等 | 推荐，待用户确认方案 |
| 任意规则表达式/大模型自动解析 | 可扩展的条件更多 | 规则歧义、验证与权限范围大 | 首期不做 |

## 8. 待确认的产品边界（不擅自实现）

1. 已确认：停用或删除规则后，不再发送该规则及已有倒数、待处理事项；历史保留。重新启用后是否恢复旧事项尚待确认。
2. 已确认：股票移出观察池后停止新触发及已有倒数、待处理提醒，保留历史。重新加入是否恢复旧事项另行确认。
3. 规则修改后，已有事项保留旧版本；再次触发新版本时是否替代同一规则的旧倒数？建议同一逻辑规则始终只保留一个当前事项。
4. 首次上线是否回看最近几个交易日初始化倒数？建议只从启用后的新收盘日产生正式触发，回看仅预览，不自动发历史提醒。
5. “已处理”是否仅到期后可标记，以及误操作是否可撤销？建议到期后可标记、支持撤销并保留日志。
6. 没有自动规则、只有人工规则时仍发送；所有规则都停用时是否发送空卡片，需要确认。
7. 本地机器漏跑、行情缺数时如何提示与补检；不得用旧数据伪装当天结果或补发多个历史排程日。

## 9. 验收标准

- 跌幅恰好 -5% 不触发；严格更低触发；缺相邻日数据明确未知。
- T+3按美股交易日历计算，覆盖周末、整日休市、半日市、夏令时；北京时间14点文案对应正确交易日。
- 连续两次大跌只按最近一次倒数；旧记录可追溯，重复运行不重复建事项。
- 卡片增删改停、拖动排序重启后保留；历史规则版本和快照不被编辑覆盖。
- 人工检查项从不自动判定通过；已处理从不等同于成交。
- 到期未处理每天提醒，处理后停止；无触发仍发规则表。
- 观察提醒与恐慌日报独立去重、独立回执；未知结果不重发。
- 页面与飞书快照的规则版本、顺序、日期和清单一致；来源缺数显示可见。
- 现有行情、恐慌公式、复盘账本和日报推送回归不受影响。

## 10. 推进顺序

确认本稿中的边界 → gstack工程方案评审 → 冻结PRD → 小步骤开发 → 本地验证 → 版本记录 → GitHub提交与新tag → 信号更新合入复盘 → 本机加载与实际验收。当前只做需求与原型，不提前发布。

用户下一步：先确认停用/删除规则时已有提醒如何处理，再补充一条真实的人工开仓检查项，作为卡片内容验收样本。

## 本次实现采用的保守默认

- 用户授权继续开发基础功能，期权人工检查文字留待后续讨论，不虚构知识条目。
- 首次启用从下一份尚未收盘的新交易数据开始，不回填启用前历史；后续若要回看，单独提供预览与确认流程。
- 停用/删除、移出观察池停止相关提醒；恢复启用创建新生效版本，不重新激活旧事项。
- 已处理可撤销，但存在后续触发或规则停用时不能恢复旧事项；修改与操作均留日志。
- 无启用规则时不发空消息；有规则但无股票触发时仍每天发规则。
- 发布当天不补发新规则提醒，从下一排程日开始；相同目标和排程日独立去重。
