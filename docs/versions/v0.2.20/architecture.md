# 架构与迁移方案

## 目标

`feardeskreview`仓库 → 网页5191（信号+日报+复盘）→ 项目内信号D1库；私人核算18761 → `.review-state/`私人账本。日调度脚本同仓库 → 5191，不经过旧5173代理。

## 迁移顺序

1. 核对两边数据库、原调度状态、私人运行目录及后台配置，形成备份清单。
2. 暂停daily、停止server和review进程，确认5173/5191/18761无监听，无写入者。
3. SQLite在线备份API离线复制信号库：先备份复盘旧信号库，再复制完整46只股票的信号库到复盘仓库同绑定位置，检查完整性和表行数。
4. 复制调度config/state（包括sent/sending/unknown）到复盘仓库忽略目录，不输出凭据。私人运行状态复制到本仓库忽略目录，SQLite文件用backup，原证据路径仍保留，原目录不删。
5. 修改macOS后台任务：review使用当前仓库本机state；daily使用当前仓库脚本；旧server停用并保留plist备份。
6. 启动唯一入口；验证旧端口关闭、两类数据完整及今日发送去重。验证不额外发飞书。

## 回退

停止新daily/review，先保存新库与新去重状态，不丢失任何已发或不确定回执；恢复原plist与原数据库路径，再核对发送围栏。不可直接覆盖当前状态为旧备份，否则可能重复推送。保留原目录，不自动回退或重发。

## 已识别风险

- 两个Miniflare实例不能并发写同一库；必须停写且只有一份生效。
- 去重JSON和SQLite投递记录要一起迁，且发送结果unknown不转pending。
- 复制私人账本时连同证据和运行配置；不重新初始化空库。
- 虚拟环境不盲目移动；当前Python解释器保留路径，只统一应用源码和运行数据入口。
- 当前工作区已有私人复盘功能改动需保留，不能reset或混入无关提交。
